# WorkspaceBench: run it on your lens

This folder runs OpenAudit's **WorkspaceBench 2026-11** on a workspace lens that you made. Each question is a prompt to Qwen3.6-27B that makes the model hold a concept that it does not write: the middle step of a two-hop fact, a rhyme that it plans, the correct form of a misspelled word. Your lens reads the residual stream at layers 20 to 60 (each fourth layer) at the positions of each family's read plan. Then a Claude judge (or a regex, for some families) checks if the readouts show the target. The headline is `macro_score`, the mean pass rate over the families.

Version 2026-11 has 10 families: `buggy_code`, `directed_modulation`, `model_specific_directed_modulation`, `multihop`, `multilingual_mt`, `multilingual_multihop`, `multilingual_typo`, `poetry`, `relational_multihop` and `typo_mt`.

Version 6be6304-fast-safety is the default version, and our setting for new runs. See [Version 6be6304-fast-safety](#version-6be6304-fast-safety).

Each version runs its own [workspace-bench](https://github.com/camilablank/workspace-bench) commit with OpenAudit's patch for that commit. `instruments/<version>.json` names both (`workspaceBench`), and the patches are in `patches/`. Version 2026-11 is at `2617613`, the commit of our own runs. `scoring.py` gives the scores from the judge output with the rules of our import script.

A version name that starts with a commit (`6be6304-fast-safety`) tells the upstream commit and the subset. A new upstream commit gets a new version: the old versions keep their commits and patches.

## Steps

You need Linux, an NVIDIA GPU with CUDA, `git`, `python3` and [uv](https://docs.astral.sh/uv/). Set `ANTHROPIC_API_KEY` for the Claude judges (or `OPENROUTER_API_KEY`: then the Claude calls go through OpenRouter). The smoke tier uses a Gemini judge through OpenRouter, so it needs `OPENROUTER_API_KEY`.

```bash
cd evals/workspacebench
./setup.sh                                                                  # the default version's workspace-bench, patch and Python environment
./run.sh --lens my_lens.pt --out out/my-lens                                # smoke tier, Qwen/Qwen3.5-0.8B
./run.sh --lens my_lens.pt --model Qwen/Qwen3.6-27B --batch --out out/my-lens  # full tier
```

`run.sh` stops if the version's workspace-bench folder (`.workspace-bench/<commit>`) is not at its commit with its patch. Then run `./setup.sh --version <version>` again.

### Tiers

| Tier  | Model               | What it tells you                                                          | Time and cost                                                                                             |
| ----- | ------------------- | -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| smoke | `Qwen/Qwen3.5-0.8B` | The lens loads and the run works: 3 families, 2 questions each. No scores. | A few minutes on one GPU, and a few cents of judge calls                                                  |
| full  | `Qwen/Qwen3.6-27B`  | The scores, and your rank next to our lenses                               | A token lens: about 10 minutes of readouts on one H100, and about $50 to $160 of API calls with `--batch` |

The full tier needs Qwen3.6-27B in bf16 on one GPU (80 GB). A text lens, which writes text for each cell, takes much longer: our Oracle Lens took about 12 H100-hours.

API cost of our full runs of version 6be6304-fast-safety, with `--batch` (from the `ledger.jsonl` files): the J-Lens $45, the Oracle Lens $113 and the J++ Lens $158. The Claude judge is most of it, and the GPT-6 Luna summarizer is $19 to $38. A lens whose readouts give the judge more to read costs more. Each run again costs as much again.

`--batch` sends the Claude calls through the Anthropic Batch API. It costs half as much, but a batch can take some hours. Without it, the judge calls cost about twice as much.

Other flags:

- `--limit N`: only the first N questions of each family, to debug. Do not submit a run with `--limit`.
- `--families a,b`: only these families. Do not submit it: a run of the version needs all of its families.
- `--judge-only`: judge the readouts in `--out` again, with no GPU work.
- `--produce-only`: only the readouts, with no judge and no API key. Add `--shard i/n` to read every n-th question, from question i, on n GPUs. Then `python3 merge.py <out> <shard outs...>` and `--judge-only` on `<out>`.
- `--judge-model`: one judge model for all families. Use it as a screen only: our scores use the judge of each family.
- `--version`: the instrument version (default 6be6304-fast-safety). Run `./setup.sh --version <version>` first, and use a different `--out` for each version.

## Your lens

Give one of these two files to `--lens`:

1. **A `.pt` file in the J format** (a linear lens):

   ```python
   {"J": {layer: Tensor[d_model, d_model]}, ...}
   ```

   The file needs a `J` for each read layer (20, 24, ..., 60). The harness reads the top 10 tokens of `J[layer] @ h` with one of two readouts. Choose it with `--readout`:
   - `norm` (default): `W_U · norm(J·h)`, with the model's final norm. Our J++ Lens uses it.
   - `cosine`: `(W_U·J·h) / ‖Jᵀ W_U[t]‖` for each token `t`, with no norm. Our J-Lens uses it.

2. **A `.py` file with `load_reader(model_name)`** (any lens, also a text lens). The function gives an object with `bind(backend)` and `read(h, layer)`, and optionally `read_batch(hs, layer)` and `layers`. `read` gives a `Readout`: `tokens` and `scores` for a token lens, or `samples` (a list of texts) for a text lens. See `examples/logit_lens_reader.py`.

`results.json` gives the file, its sha256 and the readout (for a `.pt` file) in `lens`.

## The instrument

OpenAudit's instrument is not the paper's method, and a later version can change it. `instruments/<version>.json` has the settings of each version.

- **One judge call for each question.** WorkspaceBench's method makes a digest of each layer, merges the digests, and then judges. Ours sends all readout lines of a question to the judge at one time (`summ_direct=1`), with a note that each line is one raw sample (`summ_direct_note=1`). We use the note because it is true, not because of a score gain: its effect was inside the run-to-run noise.
- **Agreement and cost.** On the J-Lens, with a Claude Opus judge, on 5 families × 24 questions: their method has a pass rate of 0.38, at $0.448 for each question and 1,688 s. Ours has 0.42, at $0.079 for each question and 121 s. Ours gives the same verdict as theirs on 96% of questions. Theirs agrees with its own repeat on 94%.
- **A text lens.** On the Oracle Lens, ours against theirs: poetry 0.58 and 0.70, directed_modulation 0.58 and 0.58, multihop 1.00 and 1.00. The cost was $4.21 and $44.67. Ours is weaker when a rhyme shows in only one to three sample lines (poetry: 0.52 to 0.54 against 0.67).
- **Judge effort.** Low. The default effort did not raise the Oracle Lens poetry score.
- **Large questions.** If the largest question of a family is over 200,000 tokens, the family uses its lite read sites. If it is still too large, it uses WorkspaceBench's digest method. No family of version 2026-11 needs this.
- **The paper's numbers.** The paper used a Gemini 3.8 Flash judge for most families, so its numbers are not comparable with ours.

`instruments/2026-11.json` also lists the `later` families: the patch can run them, but they are not in this version. A run with them is partial.

## Version 6be6304-fast-safety

```bash
./setup.sh --version 6be6304-fast-safety
./run.sh --version 6be6304-fast-safety --lens my_lens.pt --model Qwen/Qwen3.6-27B --batch --out out/my-lens-fast-safety
```

- **The method.** WorkspaceBench's own method (Method 1) on its fast-safety subset (`fast-safety-v1`, `wsbench --fast-safety`): 24 families, with `agentic_misalignment` and `jailbreak_recognition`. A summarizer writes notes on the readouts of each layer. Then the judge of each family reads the notes.
- **The summarizer.** GPT-6 Luna, through OpenRouter, so the run needs `OPENROUTER_API_KEY`. With `--batch`, the Claude calls go through the Anthropic Batch API, and the Luna calls go through OpenRouter. Three families keep their default summarizer:
  - `introspection`: Luna drops the concept from its notes.
  - `model_specific_directed_modulation` and `multilingual_typo`: in these regex families, the summarizer is the scorer.
- **Agreement.** With Luna notes and the Claude judge, the verdicts agree with all-Claude Method 1 on 92% of questions (94% without introspection). All-Claude Method 1 agrees with its own repeat on 94%.
- **The macro.** WorkspaceBench's own macro (`results.macro`), with all of its rules. `results.json` gives the families that it excludes, and why, in `macroExcluded`. Upstream counts a family as complete only with its default summarizer. Our patch adds `WSB_DIGEST_OF_RECORD`, and `run.py` sets it to the version's summarizers (`summarizersOfRecord` in `results.json`), so Luna families can be complete.
- **Reads.** The fast subset reads only its items and sites, at full reads. There is no lite fallback: the digest takes a question of any size.
- **Our lenses.** `./run_ours.sh` runs the J-Lens, the J++ Lens and the Oracle Lens (`lenses.json`, at pinned Hugging Face revisions) on Qwen3.6-27B with `--batch`, into `out/ours-<version>/<lens>`. `LENSES=jlens,jpp` runs some of them. Other arguments go to `run.sh`.
- **Imported readouts.** `python3 import_readouts.py --out <out> --from <dir> --source <url>` copies readouts made elsewhere into a run, for `--judge-only`. `results.json` gives the source and sha256 of each file in `readoutSources`.
- **Export.** `uv run --no-sync --project .workspace-bench/6be6304 python export.py --run out/ours-6be6304-fast-safety` writes `export/<family>.jsonl` (each read item: its prompt, its readouts and the judge's verdict and notes, for each lens) and `export/run.json`. It fails if the scored items do not give the family values of `results.json`. A knowledge_cutoff item from nocot-bench keeps only its id and results: nocot-bench asks that its questions are not republished.

## Rules

Do not fit your lens, or choose its settings, on WorkspaceBench items. Fit data such as wikitext is good.

## Output

`out/<name>/`:

- `results.json`: schema `openaudit.workspacebench.results/1`. For each model: the tier, if the run is partial, the lens file and its sha256, the harness commits and the patch sha256, the instrument (version, judge, effort, route), the metrics of each family, the failed families, the judge spend, the time and the GPUs.
- `readouts/<family>.jsonl`: the readout of each cell (question, layer, position).
- `judge/<family>/`: the judge's `results.json`, `run.log` and `ledger.jsonl` (one line for each judge call, with its tokens and cost).
