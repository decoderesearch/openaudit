# Workspace Lens evals: run them on your lens

This folder runs the OpenAudit Workspace Lens evals on a lens that you made:

- **Workspace Lens Readout 2026-10.3**: does the lens read out the hidden words of a prompt at the middle layers? The headline is `recall_at_10`.
- **Workspace Probe Swap 2026-11**: if we edit the residual along the lens's direction of one word to another, does the model's answer change to match? The headline is `swap_top1`. Only linear lenses (a `.pt` file) get this eval.

It runs the same code as our own runs: the pinned [jpp_lens](https://github.com/safety-research/jpp_lens) commit and `data/scripts/rlens-fit`. The logit lens runs next to your lens as the baseline. `scoring.py` gives the scores from the output files with the rules of our import script.

## Steps

You need Linux, an NVIDIA GPU with CUDA 12.8, `git` and [uv](https://docs.astral.sh/uv/).

```bash
cd evals/workspace-lenses
./setup.sh                                                        # jpp_lens and its Python environment
./run.sh --lens my_lens.pt --out out/my-lens                      # smoke tier, Qwen/Qwen3.5-0.8B
./run.sh --lens my_lens.pt --model Qwen/Qwen3.6-27B --out out/my-lens  # full tier
```

Each run adds the model to `out/my-lens/results.json`, with the sha256 of its lens file. A new run of a model replaces the old one.

You do not need to run all of them: one model is enough. A lens on another model is also good. Other models use the layers `round(n_layers * i / 8)` for `i` = 1 to 7. The smoke model's layers are 3, 6, 9, 12, 15, 18, 21.

`--limit N` runs only the first N readout items, to debug. Do not submit a run with `--limit`.

Scores on different GPU types can be different by about 0.005, because of bf16 numerics. Our runs use H200 GPUs. For example, an identity lens on Qwen/Qwen3.5-9B on an RTX 5090 gets `recall_at_10` 0.245, and our logit lens on an H200 gets 0.246.

## Your lens

A lens maps a residual at a middle layer into the basis of the last layer. The harness then applies the model's final norm and unembedding. Give one of these two files to `--lens`:

1. **A `.pt` file in the J format** (a linear lens). Both evals run.

   ```python
   {
       "J": {layer: Tensor[d_model, d_model]},
       "source_layers": [...],
       "d_model": int,
       "n_prompts": int,
   }
   ```

   `transport(h, layer) = J[layer] @ h`. The file needs a `J` for one or more readout layers of the model. A file that `BaseLens.save` of jpp_lens wrote is also good. `examples/make_identity_j.py` writes an example.

2. **A `.py` file with `load_lens(model, layers, hf_model_name)`** (any lens). Only the readout eval runs. The function gives an object with `transport(residual, layer)`: a float32 tensor `[..., d_model]` in, a tensor `[..., d_model]` out. If the object has `layers`, the harness uses only those readout layers. See `examples/identity_lens.py`.

Your lens and the baseline use the readout layers that your lens has. A lens with fewer layers can get a lower score, because the readout score takes the best layer of each hidden word. `results.json` gives the layers of the run in `layers`.

The harness checks the lens before the run: the model name and `d_model`, the layers, and a `transport` of random input to the correct shape with finite values.

### Self-test

The identity lens reads out the same as the logit lens. A run of it must give your lens and the baseline the same scores:

```bash
uv run --project .jpp_lens --extra cu128 python examples/make_identity_j.py \
  --d-model 1024 --layers 3,6,9,12,15,18,21 --out out/identity.pt
./run.sh --lens out/identity.pt --out out/identity
```

## Rules

The readout eval items have a fit split and a held-out split (`split_fitting_items`, seed 0). The score uses only the held-out items. You can fit on the fit split (the J++ Lens does). Do not use held-out items or probe swap items to fit your lens or to choose its settings.

## The recipe

Tell us how you made the lens. This is optional, but it helps us trust the results: a lens that is fit or tuned on the eval items can get a high score that does not generalize. See [`submission/README.md`](submission/README.md).

## Output

`out/<name>/`:

- `results.json`: schema `openaudit.workspace-lenses.results/1`. For each model: the tier, the lens file and its sha256, the harness commits, the layers, the grade file, and the metrics of your lens and of the baseline for each eval.
- `<model>_readout_samples.jsonl.gz`: for each item and layer, the top tokens and the rank of each hidden token.
- `<model>_probe_swap_success.csv`, `_best_scale.csv`, `_trials.parquet`, `_header.json`: the swap results.
- `<model>_correctness.csv`: the model's grade of the eval items, if `correctness/` has no file for the model. The readout eval uses only the items that the model answers correctly.
